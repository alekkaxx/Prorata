# prorata

Биллинг-движок подписок: события → инвойс с объяснением каждой строки.
Библиотека, чистые функции. НЕТ: HTTP, БД, CLI, конкурентности, LLM в рантайме.
Витрина AI-конвейера: этот файл маршрутизирует РАЗРАБОТКУ по моделям. Контекст проекта — PLAN.md.

## Роутинг задач по моделям

| Задача | Агент | Гейт |
|---|---|---|
| дизайн ядра/API, округления, упавшие property | architect (opus) | ревью человека |
| правило по спеке + тесты | builder (sonnet) | golden + property + architect |
| фикстуры, табличные тесты, механика, доки | mechanic (haiku) | make check |

Эскалация: 2 фейла гейта подряд → тир выше. Публичный API или инварианты → только architect.
Обратная эскалация: builder обязан остановиться и вернуть наверх ошибку в спеке (арифметика, дыра), а не подкрутить тест под неё.
Вниз: без спеки в specs/ builder и mechanic не стартуют.

## Инварианты (нарушение = стоп и architect, не «подкрутить тест»)

- Деньги не создаются и не исчезают: сумма allocation == исходной сумме.
- Расчёт идемпотентен: тот же вход → байт-в-байт тот же инвойс.
- Кредит ≤ фактически уплаченного.
- Каждая строка инвойса несёт RuleID и объяснение.

## Конвейер правила

спека (architect) → фикстуры+падающие тесты (mechanic) → реализация (builder)
→ гейт (architect, вердикт в спеку) → строка в README-экономику.
Ритуал: skill add-rule.
Сжатый режим: по решению владельца mechanic-шаг (фикстуры+падающие тесты) может выполнить builder — след в теле коммита.

## Структура

Одно правило = rule_<name>.go + specs/NN-<name>.md + golden/NN-*.json.
Ядро: money.go period.go plan.go event.go invoice.go engine.go — менять только через architect.

## Стиль кода

Все комментарии — godoc, на английском. Русских комментариев в .go-файлах не бывает.

## Без явной просьбы — НЕ делать

- Не создавать файлы вне конвенции (helpers.go/utils.go запрещены).
- Не менять ядро и публичный API в задачах уровня builder/mechanic.
- Не расширять скоуп (HTTP/БД/CLI/валюты) — витрина, не продукт.
- Не читать golden целиком — только диффы упавших.

## Проверка

make check = go build + go vet + go test ./... (property на pgregory.net/rapid).
Перед коммитом — зелёный make check, других условий нет.
