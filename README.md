# prorata

[![check](https://github.com/alekkaxx/Prorata/actions/workflows/check.yml/badge.svg)](https://github.com/alekkaxx/Prorata/actions/workflows/check.yml)

Биллинг-движок подписок: события → инвойс с объяснением каждой строки.
Библиотека, чистые функции. Нет HTTP, БД, CLI, конкурентности.

Настоящая цель проекта — не движок, а **витрина AI-конвейера**: как разработка
маршрутизируется по моделям в зависимости от сложности задачи. Контекст и мета-цель —
[PLAN.md](PLAN.md), правила станка — [CLAUDE.md](CLAUDE.md).

## Если у вас десять минут

1. **Сценарий ниже** — что движок считает и почему каждая строка объясняет себя (1 мин).
2. **[CLAUDE.md](CLAUDE.md)** — станок целиком: роутинг по тирам, инварианты, доменные
   решения, которые нельзя переоткрывать (4 мин). Это главный артефакт проекта.
3. **`git log`** — след конвейера: команды и фактические числа в разделе
   [«Проверить станок за пять минут»](#проверить-станок-за-пять-минут) (2 мин).
4. **[specs/00-core.md](specs/00-core.md)** — как принимаются решения: каждое в формате
   «решение → почему → **отвергнутая альтернатива**», внизу вердикт гейта (3 мин).

Код движка читать не обязательно: всё, что он делает, видно из сценария и золотых фикстур.

## Сценарий-витрина

Юзер стартует месячный **Pro** ($20/мес) 1 января. 13 января применяет промокод
**WELCOME20** (−20% на первый заряд) и тем же днём апгрейдится на годовой
**Business** ($480/год). Период счёта — 2026-01-13 … 2027-01-13. Что в инвойсе?

| Правило | Строка | Сумма |
|---------|--------|------:|
| `prorate.credit` | pro-month: unused 19/31 days 2026-01-13 to 2026-02-01 | −$12.26 |
| `prorate.charge` | business-year: full period 2026-01-13 to 2027-01-13 | +$480.00 |
| `promo.percent` | WELCOME20: −20% off 480.00 | −$96.00 |
| | **Итог** | **$371.74** |

Каждая строка несёт `RuleID` и человекочитаемое «почему»; итог — точная сумма строк,
без потери копейки. Эталон сценария зафиксирован в
[golden/04-promo-showcase.json](golden/04-promo-showcase.json) (суммы в центах:
−1226, 48000, −9600, итог 37174).

## Как это написано

Проект собран конвейером из трёх тиров моделей, каждый со своим гейтом:

- **architect** (opus) — дизайн ядра и публичного API, спеки правил в `specs/`,
  разбор упавших property-тестов, гейт-ревью (вердикт пишется в спеку, секция `## Gate`).
- **builder** (sonnet) — реализация одного правила по готовой спеке + его тесты,
  до зелёного `make check`.
- **mechanic** (haiku) — golden-фикстуры, табличные тесты по спеке, механика, доки.

Роутинг задач по тирам и правила эскалации — в [CLAUDE.md](CLAUDE.md); мета-цель и
бэклог — в [PLAN.md](PLAN.md). Сами агенты лежат в репозитории: [.claude/agents/](.claude/agents/)
(три файла с `model:` в frontmatter) и ритуал [.claude/skills/add-rule/](.claude/skills/add-rule/).
Каждый шаг конвейера **виден в git-истории**: префиксы коммитов размечают роли
(`spec(` → `test(` → `feat(` → `gate(`, ядро — `core(`, экономика — `docs(economy)`),
а тир исполнителя проставлен строкой `Tier:` в теле коммита.

## Проверить станок за пять минут

```bash
make check                                                          # build + vet + golden + property
git log --format='%b' | grep '^Tier:' | sort | uniq -c | sort -rn   # кто сколько сделал
git log --format='%s' | sed 's/(.*//' | sort | uniq -c | sort -rn   # шаги конвейера
```

Фактическое распределение на момент десятого гейта — 62 коммита, все десять правил закрыты:

| Тир | Коммитов | Чем занят |
|---|---:|---|
| architect | 36 | спеки, гейты, ядро, доки — места, где принимаются решения |
| mechanic | 14 | golden-фикстуры и падающие табличные тесты |
| builder | 10 | реализация правил (2 из них в сжатом режиме) |

Architect лидирует по числу коммитов — так и задумано: на дорогой тир вынесены решения,
а не объём. Собственно реализация десяти правил уместилась в 10 коммитов дешёвого builder'а,
механика тестов — в 14 коммитов самого дешёвого mechanic'а.

Два коммита из этих 62 строки `Tier:` не несут — конвенция дошлифовывалась по ходу проекта.
Это видно той же командой и здесь не заметается: витрина показывает станок как есть.

## Контекст, ритуал, преграда — три разных механизма

Пропущенные `Tier:` — не грязь, а показание прибора. Правило было записано в CLAUDE.md, то есть
как **контекст**: модель его читает и обычно соблюдает, но гарантии нет — 62 попадания из 65.
Правило, которое обязано выполниться, должно жить не там, а в **преграде**:

```bash
git config core.hooksPath .githooks   # включить один раз на клон
```

[.githooks/commit-msg](.githooks/commit-msg) отклоняет коммит без строки `Tier:` независимо от
того, что решила модель. Те же 65 коммитов дали бы 65 попаданий.

Отсюда разделение, по которому собран весь станок:

| Механизм | Где живёт | Для чего |
|---|---|---|
| контекст | [CLAUDE.md](CLAUDE.md) | договорённости, инварианты, доменные решения — грузятся в каждую сессию |
| ритуал | [.claude/skills/add-rule/](.claude/skills/add-rule/) | многошаговый процесс, подгружается по требованию |
| преграда | [.githooks/](.githooks/) | то, что обязано выполниться при любом решении модели |

История коммитов намеренно не переписывалась: для витрины процесса подчищенный `git log` стоил бы
дороже, чем два честных пропуска, которые и показали, где нужна преграда вместо просьбы.

## Что показала экономика

Роутер работает так, как задуман. Простые и типовые правила (01–04, 07) доезжают
дешёвым тиром **builder** с первого захода — дорогой architect на них не тратится.
Ловушки ловятся эскалацией: правило 05 — **единственный** двойной заход, и это не
дефект реализации, а **обратная эскалация** — builder уперся в арифметическую ошибку
спеки (46774 вместо 45774) и остановился, вместо того чтобы подкрутить тест под
неверную спеку. Правило 06 доехало ещё дешевле — тиром **mechanic** без единой строки
нового кода (доказательная спека поверх правил 02/03). А ядро, спорная арифметика
округления и все гейты остались за дорогим тиром **architect** — там, где решения
принимаются, а не вспоминаются. Дешёвым тирам можно доверять именно потому, что за
ними стоит машинная верификация (`make check`: build + vet + golden + property) и
гейт architect с вердиктом в спеку.
